# CLAUDE.md: Botbench

A workbench for the owner of a LEGO Robot Inventor 51515 and an EV3 31313: plan which parts go in which ports, rehearse the robot in a 2D simulator, export Pybricks MicroPython, and drive a real Inventor Hub from the page over Web Bluetooth. The optional decision layer (TypeSafe Jev) runs on a laptop bridge, never in the browser.

**Live:** botbench.neorgon.com · **Port:** 8898

## Run

```bash
make serve                  # http://localhost:8898, ES modules need HTTP
node --test test/*.test.mjs # build, brain, export and link protocol, no browser
```

## Architecture

| Module | Owns |
|---|---|
| `js/catalog.js` | Hubs, devices, kits, chassis archetypes, firmware paths, extra hardware. Every hardware fact lives here |
| `js/build.js` | Port validation (connector family, EV3 motor vs sensor ports, parts in the box), capabilities, the combination matrix |
| `js/brain.js` | Rule-table runner, the four modes, `facts()` (numbers to categories), the Jev request, the local stand-in decider |
| `js/sim.js` | Arenas painted on a canvas, differential-drive kinematics, sensor models. No drawing |
| `js/simview.js` | Canvas, clock, brain in the loop; also the virtual hub when the Link tab attaches |
| `js/link.js` | Pybricks BLE profile (UUIDs, command and event bytes), facts line, stdin frames, `createLink` over a transport; `bleTransport` and `virtualTransport` |
| `js/linkpanel.js` | The Link tab: connect, status, facts, teleop pad, mode buttons, stand-in decider, REPL paste experiment |
| `js/export.js` | Pybricks programs for either hub (rules, modes with teleop) and `bridge.py` for Jev |
| `js/projects.js` | The project ladder |
| `js/state.js` | Workbench state and validated persistence |
| `js/render.js`, `js/simpanel.js`, `js/events.js` | Panels, simulator controls, all listeners |

Vendored from `packages/neorgon-ui/`, never edit in place; run the sync script instead: `js/neorgon-header.js`, `js/neorgon-footer.js`, `js/neorgon-beacon.js`, `js/neorgon-dom.js`, `js/neorgon-persist.js`.

## Data

One localStorage key, `botbench-site:workbench` (owned kits, both builds, arena, brain, link source), written through `neorgon-persist.js` and validated field by field on load. Nothing else persists; the hub link and the simulator are session state.

## Conventions

- Zero build step. Plain ES modules loaded by `js/app.js`.
- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- No single JS file over ~500 lines. It currently holds.
- One byte table for the hub: `MODE_CODES` and `TELEOP` in `js/link.js` are read by the exporter, the virtual hub and the Link tab. Add a mode or a teleop key there and nowhere else.

## Gotchas

- **The hub never sees a number.** `facts()` turns readings into categories (blocked, line edge, red zone) before anything asks Jev, because comparing numbers is on Jev's documented weak-spot list. Keep thresholds in code, on both sides: `brain.js` for the simulator and `factsFn` in `export.js` for the hub, and they must agree.
- **A thin line is latched.** The 22 mm line passes the colour sensor in a tenth of a second and facts go out every 500 ms, so both the simulator and the exported program remember "crossed a line" between reports. Without it the mode switcher never found the line again after avoiding a box.
- **Kit ids look like integers.** `KITS` is keyed `51515` and `31313`; JavaScript orders integer-like keys numerically, so `Object.values` puts the EV3 first. Iterate `KIT_ORDER`.
- **The simulator pauses when the page is hidden.** The loop is `requestAnimationFrame`; the Step button runs six ticks synchronously and is how the headless browser tests drive it. A byte written through the link lands on a microtask, so a test that clicks and then steps in the same task sees the effect one phase late.
- **Web Bluetooth needs a user gesture and https.** `requestDevice` is reached synchronously from the Connect click; put nothing async before it. Only Chromium browsers have it; the Link tab says so instead of failing.
- **One central per hub.** Pybricks Code and this page cannot both hold the hub; the Link tab tells the visitor to disconnect Pybricks Code first.
- **The REPL paste path is untested on hardware** (2026-11-02). It is behind an "Experimental" disclosure and paces every line on its echo; if a real hub rejects it, the Hub output pane is the diagnostic.
- **The EV3 has no Bluetooth LE.** Its modes program takes modes from the brick buttons and prints facts; neither the Link tab nor `bridge.py` can reach it.
- **The IR sensor is not millimetres.** The EV3 infrared sensor reports 0 to 100 relative proximity; the export scales it by about 7 mm per unit and says to calibrate.
